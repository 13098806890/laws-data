# 🏛️ База данных законов и нормативных актов Китая

[中文](README.md) · [English](README.en.md) · [LICENSE](LICENSE)

> Структурированный открытый набор данных действующих законов и нормативных актов КНР — исходные документы, структурированный JSON, база данных SQLite и полные тексты Markdown для поиска, исследований и разработки приложений.

**Лицензия**: [MIT](LICENSE). Правовые тексты взяты из официальных открытых источников (не охраняются авторским правом); структурированные данные и переводы также открыты по MIT — свободное коммерческое использование, распространение и модификация.

**Быстрый старт**: скачайте готовую базу или соберите сами — см. [Быстрый старт](#-быстрый-старт) ниже.

## 📦 Источник данных

**Основная библиотека**: все исходные документы взяты из **[Национальной базы данных законов и нормативных актов](https://flk.npc.gov.cn/)** (国家法律法规数据库) — официальной платформы Законодательной комиссии ПК ВСНП, загружены в формате docx/doc и обработаны конвейером проекта.

Несколько файлов, чьи исходные docx отсутствуют или повреждены, заменены текстом, извлечённым с сайта ВНС — см. `sources/_web_sources/README.md`.

**Вестник ВНС**: скачивается с [gongbao.court.gov.cn](https://gongbao.court.gov.cn) скриптом `scripts/fetch_gongbao.py` в каталог `最高人民法院公报/` (JSON).

## 🔄 Основной конвейер

**Вход**: `python3 scripts/pipeline.py`

Конвейер выполняет семь этапов последовательно и пересобирает всё с нуля (без инкремента), ~5–10 минут за запуск.

### Этап 1: `docx_to_json` — исходные файлы → структурированный JSON

**Вход**: `.docx` / `.doc` / `.txt` из `sources/` (`.txt` имеет приоритет над одноимённым `.docx`, используется для замены дефектных оригиналов)

**Выход**: `.json` в `json/`, по одному файлу на закон

**Шаги**:

1. **Предзагрузка xlsx-индекса** (`domain.py`): в каждом каталоге источников есть `法律法规文件目录_*.xlsx` с 4 колонками (название | дата публикации | дата вступления в силу | категория). Индекс `{название}_{YYYYMMDD}` → `{effective_date, category}` — авторитетный источник, перекрывает извлечение из текста.
2. **Извлечение абзацев** (`converter.py`): чтение абзацев docx / строк txt; распознавание органа издания (точное совпадение по белому списку из 12 органов) и номера документа (регэксп `аббр. органа〔год〕номер`).
3. **Дата вступления в силу** (`effective_date.py`): из абзацев обнародования; значение xlsx имеет приоритет.
4. **Распознавание структуры** (основной цикл converter): `第X编` → часть; `第X章` или заголовки с китайскими цифрами (`一、管辖`, часто в судебных толкованиях) → глава; `第X节` → раздел; `第X条` → статья (с разбивкой слитых абзацев); короткие файлы без структуры → одна статья с полным текстом.
5. **Сборка иерархии** (`structure.py`): вложенные структуры часть/глава/раздел/статья, `global_order` по обходу в глубину, `ORDER BY global_order` восстанавливает порядок чтения.
6. **Метаданные**: `title` из имени файла (никогда не из тела docx), `category` из xlsx, `legal_domain` (сначала `LAWS_REPO_PATH`, затем ручные дополнения, затем правила по ключевым словам).

**Особые случаи**:
- Гражданский кодекс имеет 7 частей; заголовок «Общие положения» жёстко прописан (отсутствует в исходнике)
- Статьи непосредственно внутри части используют плейсхолдер-главу `_DIRECT_`, лишние узлы не создаются
- Файлы в формате «九民纪要» (`1.【заголовок】текст`) предварительно преобразуются `fetch_web_sources.py` в `第N条　【заголовок】текст`

### Этап 2: `generate_law_index` — стабильные law_id

**Вход**: все `.json` из `json/`

**Выход**: `scripts/law_index.json` (постоянный индекс, ID стабильны между пересборками)

Ключ закона — `{название}_{pub_date}`; при первом появлении назначается постоянный ID (автоинкремент с 1000001). При пересборке существующие ID сохраняются, новые законы получают новые ID. Это сохраняет валидность `article_references` и других кросс-ссылок.

---

### Этап 3: `json_to_db` — JSON → SQLite

**Вход**: `json/`, `law_index.json`

**Выход**: `law_content.db` (полная пересборка, старая БД удаляется)

**Шаги**:

1. **Создание таблиц** (`builder.py`): `laws`, `nodes`, `nodes_fts` (FTS5 trigram), `nodes_fts_bigram` (FTS5 unicode61), `article_references` + индексы. Обе FTS-таблицы — **внешние таблицы содержимого** (`content="nodes"`), без дублирования текста, экономия ~175MB.
2. **Записи laws**: метаданные из JSON, стабильный ID из `law_index.json`, алиасы из `law_aliases.py`.
3. **Записи nodes** (рекурсивно): часть → глава → раздел → статья с `parent_id`, `global_order`, `part_num`, `chapter_num`, `section_num`, `article_num`; каждая статья вставляется в обе FTS-таблицы.
4. **FTS optimize** после всех вставок.
5. **Разметка толкований Вестника** (`classify_gongbao_domain.py`): назначение legal_domain для `source='gongbao'`.
6. **Экспорт меню**: `law_menu.json` (группировка по subject_area, с title_en) для бокового меню iOS.

---

### Этап 4: `extract_references` — извлечение ссылок между статьями

**Вход**: `law_content.db` (nodes)

**Выход**: `references/article_references.json` + таблица `article_references` в `law_content.db`

По всем статьям с `is_current=1` распознаются три вида ссылок:

1. **Межзаконные с кавычками**: `《Название закона》第X条`, разрешение через `art_index`; работают и краткие названия (без префикса «中华人民共和国»), и полные.
2. **Краткие названия без кавычек**: `刑法第X条` и т.п., динамические регэкспы кратких названий, сначала длинные — во избежание неоднозначности.
3. **Внутренние**: `本法/本条例/本规定第X条`; «本法第X条» в поправках к УК перенаправляется на УК и помечается `cross_law`.

**Текущая статистика**: 5 319 ссылок (2 559 межзаконных, 2 760 внутренних), разрешено 98,4%.

### Этап 5: импорт английского (`import_en.py`)

**Вход**: `json_en/` (переводы статей), `references/heading_en_map.json` (переводы заголовков)

**Выход**: `nodes.content_en`, `laws.title_en`

- Статьи сопоставляются по `article_number`, идемпотентно (`WHERE content_en IS NULL` никогда не перезаписывает)
- Заголовки структуры пишутся из `heading_en_map.json` (стабильный ключ `law_id:type:order_index`)

### Этап 6: `db_to_md` — БД → Markdown

**Вход**: `law_content.db` (законы с `is_current=1`)

**Выход**: `.md`-файлы, сгруппированные по меню subject_area (宪法与国家机构/ 民事与商事/ 刑事/ 行政与公法/ 经济、税务与金融/ 劳动与社会保障/ 诉讼与司法程序/ 其他)

Каждая статья получает якорь `<a id="art-N">`; исходящие ссылки в тексте автоматически становятся межфайловыми Markdown-ссылками.

### Этап 7: импорт Вестника (`build_gongbao_db`)

**Предусловие**: JSON-файлы в `最高人民法院公报/` (скачаны `fetch_gongbao.py`)

**Выход**: две новые таблицы в `law_content.db`; судебные толкования Вестника включаются в основные `laws`/`nodes`:

| Таблица | Описание |
|----|------|
| `gongbao_docs` | Решения + руководящие дела + судебные документы, всего 2 289; `source` различает `al`/`cpwsxd`/`sfwj` |
| `gongbao_case_law_links` | Связи документов Вестника со статьями основной БД, 3 529, разрешено 99,8% |
| `gongbao_docs_fts` | Полнотекстовый индекс FTS5 trigram (внешняя таблица) |

Судебные толкования Вестника (839, ID 3500010–3501473) не хранятся отдельно — записываются как `source='gongbao'` в основные `laws`/`nodes`. Назначение law_id строго через `scripts/law_id_registry.py` (блок-лист → встроенный json_en → law_index, три уровня), без нечёткого сопоставления.

**Отдельный запуск**:

```bash
python3 scripts/build_gongbao_db.py          # создать таблицы и импортировать (если есть — пропуск)
python3 scripts/build_gongbao_db.py --drop   # сначала удалить старые таблицы
```

**Скачивание данных Вестника**:


## 🗄️ Структура базы данных

Две SQLite-базы:

- **`law_content.db`** (~460MB) — основная БД, полностью генерируется `pipeline.py`, включает данные Вестника. **Не хранится в git**; скачать с [GitHub Releases](https://github.com/doxie/laws-data/releases) или собрать локально.
- **`law_enhancements.db`** (~128KB) — БД RAG-усиления, поддерживается отдельно скриптом `build_enhancements.py`.

### Таблицы `law_content.db`

#### 🟠 `laws` — одна строка на закон

| Поле | Тип | Описание |
|------|------|------|
| `id` | INTEGER PK | Стабильный ключ от `generate_law_index.py`, переживает пересборку |
| `title` | TEXT | Полное название из имени файла (не из тела docx) |
| `title_en` | TEXT | Англ. название, импортировано из json_en |
| `filename` | TEXT UNIQUE | Формат: `{название}_{YYYYMMDD}`, без расширения |
| `category` | TEXT | `法律` / `行政法规` / `司法解释` / `修正案` / `法律解释` / `宪法` / `监察法规` / `有关法律问题和重大问题的决定（部分）` |
| `legal_domain` | TEXT | `民法典` / `民法商法` / `刑法` / `行政法` / `经济法` / `社会法` / `宪法相关法` / `诉讼与非诉讼程序法` |
| `subject_area` | TEXT | Подтема меню (все законы с v2.0.0, записывается export_menu.py) |
| `pub_date` | TEXT | Дата публикации `YYYY-MM-DD` |
| `effective_date` | TEXT | Дата вступления в силу; xlsx авторитетен |
| `promulgation_info` | TEXT | Полный текст обнародования |
| `issuing_org` | TEXT | Орган издания (белый список из 12 органов) |
| `doc_number` | TEXT | Номер документа (法释〔2000〕29号 и т.д.) |
| `total_articles` | INTEGER | Количество статей |
| `full_text` | TEXT | Полный текст закона |
| `version_date` | TEXT | Как `pub_date`; для различения версий |
| `is_current` | INTEGER | **1 = действующий**; 0 = исторический или прямо отменённый (`repealed_by` непуст) |
| `aliases` | TEXT | Псевдонимы через запятую (民法典,民法), для расширения поиска |
| `source` | TEXT | `flk` (основная библиотека) / `gongbao` (Вестник ВНС) |

```sql
-- Поиск по псевдониму
SELECT * FROM laws WHERE is_current=1 AND (title LIKE '%民法%' OR aliases LIKE '%民法%');

-- Судебные толкования Верховного суда
SELECT title, doc_number, pub_date FROM laws
WHERE issuing_org = '最高人民法院' AND category = '司法解释'
ORDER BY pub_date DESC;
```

#### 🔵 `nodes` — части / главы / разделы / статьи в одной таблице

| Поле | Тип | Описание |
|------|------|------|
| `id` | INTEGER PK | Автоинкремент |
| `law_id` | INTEGER FK | Ссылка на `laws.id` |
| `parent_id` | INTEGER FK | ID родителя; NULL у частей |
| `type` | TEXT | `part` / `chapter` / `section` / `article` |
| `title` | TEXT | Текст заголовка; у статей совпадает с `article_number` |
| `article_number` | TEXT | Например `第一条`; NULL у структурных узлов |
| `content` | TEXT | Заголовок у структурных узлов, текст статьи иначе |
| `content_en` | TEXT | Англ. перевод (статьи + заголовки), импорт import_en.py |
| `order_index` | INTEGER | Позиция внутри родителя |
| `global_order` | INTEGER | Глобальный порядок обхода в глубину — `ORDER BY global_order` даёт порядок чтения |
| `part_num` | INTEGER | Номер части (NULL без структуры частей) |
| `chapter_num` | INTEGER | Номер главы |
| `section_num` | INTEGER | Номер раздела (NULL без разделов) |
| `article_num` | INTEGER | Целочисленный номер статьи (第十二条 → 12), для диапазонных запросов |

Примечания:
- Структура `part` есть в 9 законах (ГК, УК ×2, УПК ×2, ГПК ×3, Экологический кодекс)
- Некоторые судебные толкования используют заголовки с китайскими цифрами (`一、管辖`) вместо глав; всё равно отображаются как `chapter`
- Короткие документы без структуры (правовые толкования, ответы) — одна статья (content = full_text)

```sql
-- Полный текст закона в порядке чтения
SELECT type, title, content FROM nodes WHERE law_id = ? ORDER BY global_order;

-- Статьи 10–20
SELECT article_number, content FROM nodes
WHERE law_id = ? AND type = 'article' AND article_num BETWEEN 10 AND 20;
```

#### 🟢 `nodes_fts` — полнотекстовый поиск (≥3 символов)

FTS5 **внешняя таблица содержимого** (`content="nodes"`) — без дублирования текста, экономия ~175MB. Токенизатор `trigram`, произвольное подстрочное совпадение китайского, минимум 3 символа.

```sql
SELECT n.article_number, n.content, l.title
FROM nodes_fts f
JOIN nodes n ON f.rowid = n.id
JOIN laws l ON n.law_id = l.id
WHERE nodes_fts MATCH '合同解除' AND n.type = 'article' AND l.is_current = 1;
```

#### 🔵 `nodes_fts_bigram` — поиск коротких слов (1–2 символа)

FTS5 внешняя таблица, токенизатор `unicode61`, для запросов в 1–2 символа (`婚`, `婚姻`). Для ≥3 символов предпочтителен `nodes_fts` (trigram точнее).

#### 🔴 `article_references` — ссылки между статьями

| Поле | Тип | Описание |
|------|------|------|
| `from_node_id` | INTEGER FK | Узел-источник |
| `from_law_id` | INTEGER FK | Закон-источник |
| `from_article_num` | INTEGER | Номер статьи-источника |
| `to_node_id` | INTEGER FK | Узел-цель (если разрешено) |
| `to_law_id` | INTEGER FK | Закон-цель |
| `to_article_num` | INTEGER | Номер статьи-цели |
| `ref_type` | TEXT | `cross_law` / `self_ref` |
| `resolved` | INTEGER | 1 = разрешено к конкретному узлу |
| `raw_text` | TEXT | Исходная строка ссылки, напр. `《中华人民共和国民法典》第一千二百零八条` |

Покрывает все статьи с `is_current=1`; извлекается `extract_references.py`, обновляется вместе с конвейером.

#### `gongbao_docs` — решения / руководящие дела / судебные документы (2 289)

| Поле | Описание |
|------|------|

#### `gongbao_case_law_links` — документы Вестника → статьи основных законов (3 529)

#### `gongbao_docs_fts`

FTS5 внешняя таблица, `tokenize="trigram"`, индексирует `title`, `ruling_gist`, `keywords`, `full_text`.

```sql
-- Руководящие дела, чьё резюме содержит "善意取得"
SELECT d.title, d.case_number, d.ruling_gist
FROM gongbao_docs_fts f
JOIN gongbao_docs d ON f.rowid = d.id
WHERE gongbao_docs_fts MATCH '善意取得' AND d.source = 'al'
ORDER BY d.year DESC;

-- Какие дела Вестника ссылаются на данную статью
SELECT d.title, d.source, l.article_num
FROM gongbao_case_law_links l
JOIN gongbao_docs d ON l.doc_id = d.id
WHERE l.node_id = ?;
```

## 🤖 Агенты юридических консультаций

Три скрипта нарастающей сложности, все поддерживают провайдеров DeepSeek / Groq / Ollama.

### `test_rag.py` — базовый RAG-конвейер

Поиск по ключевым словам + фильтрация LLM: маршрутизация по доменам → извлечение ключевых слов + расширение псевдонимов → поиск FTS → фильтрация релевантности → генерация ответа.

### `legal_chain_agent.py` — агент рассуждения по цепочкам статей

Добавляет навигацию по главам и расширение цепочек ссылок: разбиение вопроса → маршрутизация → навигация по главам за статьями → дополнение FTS → расширение цепочки (автодобавление цитируемых статей) → фильтрация/ранжирование → вывод.

```bash
python3 scripts/legal_chain_agent.py -q "网购假货怎么维权"
python3 scripts/legal_chain_agent.py -q "..." --provider deepseek
```

### `legal_expert_agent.py` — многослойная экспертная система

Три слоя экспертов (координатор → 6 групп → 17 специалистов), со сбором информации (автоизвлечение известных фактов, пакетные вопросы при нехватке).

```bash
python3 scripts/legal_expert_agent.py -q "公司非法裁员我怎么办"
python3 scripts/legal_expert_agent.py -q "..." --no-interactive  # без сбора информации
```

**Зависимости**: `pip install requests` (онлайн-провайдеры); для локального Ollama нужен `ollama pull qwen2.5:3b`.

## ⚠️ Известные ограничения

- Минимальный запрос trigram-FTS — 3 символа; поиск в 1–2 символа использует `nodes_fts_bigram`
- Ссылки извлекаются только из статей с `is_current=1`
- 83 ссылки не разрешены, т.к. целевой закон отсутствует в наборе (например, 执业医师法)
- `json/` **обязан зеркалировать `sources/`** (плоско, по категориям) — нельзя реорганизовывать по `legal_domain`, иначе сломается сканирование путей в `builder.py`
- `law_content.db` не хранится в git (~460MB); скачать с [GitHub Releases](https://github.com/doxie/laws-data/releases) или собрать локально
